# Project Context and Instructions

- **Goal**: We are creating a support ticket system.
- **Email Ingestion**: We listen to an email inbox using IMAP.
- **Ticket Assignment**: Any received email related to a support ask/question needs to be assigned to a particular person for that support area.
- **Database**: We use SQLite. The SQLAlchemy engine enforces foreign keys, WAL journal mode, and a busy timeout via a `connect` event listener in `models/database.py`.
- **API Auth**: When `API_KEY`/`API_KEYS` is configured, `APIKeyMiddleware` requires `X-API-Key` on every `/api/*` request (constant-time compare against every configured key). Keep `TraceIdMiddleware` outermost and the docs/`/health` exemptions intact. The SPA must never bundle the key: the Vite dev proxy or the deployment gateway injects the header server-side.
- **CI**: `.github/workflows/ci.yml` gates commits — backend ruff (lint + format) and pytest, frontend eslint and `tsc -b && vite build`.
- **AI & RAG Architecture**: We need to architect a RAG (Retrieval-Augmented Generation) system. We will provide the mail inbox content and RAG context to the AI to analyze the type of support. Based on that analysis, the ticket will be assigned to the appropriate person.
- **KB Chunking & Caching**: Knowledge-base routing docs in `api/src/knowledge_base/` are section-level chunked in `rag.py` (split on `## ` headings; each `Document` carries `team`/`department`/`section` metadata). Loaded docs are cached by file mtime + user-email key (`_KB_DOCS_CACHE`) and the tokenized BM25 corpora are memoized by content hash (`_BM25_TOKEN_CACHE`). Escalation-trigger sections must be excluded from the BM25 assignee index (they describe routing *away* from the file's own team).
- **Multi-Provider LLM Chain**: Routing uses an ordered provider chain (Gemini primary -> OpenRouter -> Groq -> local `modelm` ModelM), each with 429 retry via `invoke_with_retry`. Remote providers must be constructed with bounded request timeouts (Gemini `timeout`, OpenAI/Groq `request_timeout`) so a dead/broken network fails fast and falls through the chain instead of hanging the IMAP sync session. The local model (`modelm/langchain_model.py`) is on by default (`USE_LOCAL_MODEL`, flip to `USE_LOCAL_MODEL_FIRST=true` to prefer it); it must stay last in the chain unless explicitly configured otherwise. BM25 retrieval/fallback is local (`rank_bm25`); `langchain-community` must not be added back — it is sunset. Assignee matching is order-independent (exact dept/name match first, then word-boundary tokens) — never reintroduce bare-substring aliases like `"it"`. The local model applies the KB escalation rule deterministically via `_apply_security_escalation`: mail with explicit account-compromise phrasing (someone else logged in, logins from unknown locations/devices, account hacked/suspicious login, breached credentials) is forced to `security_compliance` with a decisive confidence — do not convert this into bare-substring matching or extend it beyond the shipped KB "Escalation Triggers" guidance. Mail with fewer than two distinct content tokens (e.g. a bare "help") is classified as `unclassified` so it is held for human review instead of auto-assigned; a human assigns the department through `POST /api/tickets/{id}/assign`, the only path allowed to override the needs-review guard.
- **Email Forwarding**: When `EMAIL_FORWARDING=true`, `email_service.py` forwards each assigned ticket to the staff member's email over SMTP (`smtp_config`, IMAP creds as fallback). Forwarding is non-fatal (failures log a warning, counted in the sync summary) and gated — never send mail unless the env flag is set.
- **LLM Output Sanitization**: LLM JSON responses are validated before persistence (`_clean_llm_result`): category is normalized to a lowercase string, `assignee_id` is kept only when it is an int referring to a real user, `confidence` is clamped to `[0.0, 1.0]`, and `reasoning` is coerced to a short string. Confidence below `0.70` (or missing) forces `category="needs_review"` with `assignee_id=None`. Exception: when a provider's cleaned confidence is below `0.70`, the deterministic BM25 router (`_fallback_bm25`) adjudicates and upgrades the assignment only when BOTH hold — the provider still named a routable team category (not `unclassified`) AND BM25's own routing confidence is itself decisive (`assignee_id` set with router confidence `>= 0.70`); otherwise the low-confidence `needs_review` decision stands. Never let BM25 force-assign a ticket the model called `unclassified` (out-of-scope/scam scrap) or whose keyword split is a weak coin flip. Never auto-assign a low-confidence ticket on hallucinated model output alone. When every provider fails at runtime, tickets are left **unassigned** (`unclassified`) for manual review.
- **PII Redaction**: Before any remote LLM call — both `rag.py:process_ticket_via_rag` and `security_analyzer.py:analyze_suspicious` — run `pii_service.redact_pii()` over the subject/body (and sender email for the security path). Redaction covers email addresses, Luhn-validated credit cards, SSNs, phone numbers, and key-value secrets, and preserves innocent long-number/phone-shaped sequences; the original text stays in the DB. The agentic harness must likewise redact the sender and prior-ticket subjects before building its remote prompt, and `imap_service` logs only the redacted subject (never the raw subject). Never send raw PII to a third-party model.
- **Audit Trail**: `imap_service.py` persists the ticket and its lifecycle audit events (`created`, `classified`, `needs_review`, `forwarded`) in a **single transaction** (add ticket → flush → `record_audit_event(...)` → commit). `record_audit_event` (`audit_service.py`) must roll back on failure so a `PendingRollbackError` never poisons the session; audit-write failures are logged and returned as `None`.
- **Security Guardrails**: Every inbound email runs through deterministic, offline validation (`validation_service.py`) BEFORE any analyzer or LLM call. Verdicts: `pass` / `flag` / `quarantine`. Quarantined mail is persisted with `status="quarantined"`, flagged, and never auto-assigned. The optional LLM assist (`security_analyzer.py`) can only escalate `flag` -> `quarantine`, never weaken a block.
- **Frontend**: We will use React under the `/web` folder.
- **Quality Standards**: We must follow enterprise-level code quality standards and write comprehensive unit tests.
- **Logging & Trace IDs**: All application logs flow through `logging_config.setup_logging()` (single `[<trace-id>]`-prefixed format). Every HTTP request gets a trace ID via `TraceIdMiddleware` (`X-Request-ID` header when provided/sanitized, else generated `req-*`), echoed in the response header; IMAP sync runs use a `sync-*` ID because background tasks do not inherit the HTTP context. Keep loggers module-scoped (`logging.getLogger(__name__)`); never `print()`.

# Privacy Rules

- Do NOT read, output, or modify `.env` files.
- Do NOT read or output environment variables containing secrets or credentials.

# File Naming and Structure Standards

- **Backend**: Use pythonic `snake_case` for folder and file names (e.g., `services/imap_service.py`). Group files logically (e.g., `models`, `services`, `controllers`).
- **Frontend**: Components must be placed in `src/components/<ComponentName>/<ComponentName>.<extension>` (e.g., `src/components/TicketCard/TicketCard.tsx`). Use `PascalCase` for component names and their containing folders. Use `pnpm` as the package manager for the `/web` workspace.
